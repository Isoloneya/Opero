# Opero

Веб-застосунок для внутрішніх операцій невеликої компанії. Opero об’єднує складський облік, заявки на матеріали, погодження, задачі та журнал дій в одному робочому просторі.

## Проблема, яку вирішує проєкт

У невеликих компаніях залишки товарів часто ведуться в Excel, заявки надсилаються через месенджери, а погодження відбуваються усно. Через це важко встановити актуальний залишок, стан заявки, відповідального працівника та історію прийнятих рішень.

Opero створює єдиний робочий простір для контролю складу, заявок, погоджень і задач.

## Основні можливості

- автентифікація користувачів через JWT;
- ролі адміністратор, менеджер, комірник і працівник;
- керування користувачами, складами та товарами;
- облік надходжень, видач і поточних залишків товару;
- контроль товарів із низьким залишком;
- створення заявок на видачу або закупівлю;
- погодження, відхилення та видача товару за заявкою;
- створення, призначення та контроль внутрішніх задач;
- дашборд з ключовими показниками;
- журнал дій;
- пошук, фільтрація, сортування та пагінація;
- адаптивний інтерфейс.

## Встановлення

```bash
git clone https://github.com/your-username/opero.git
cd opero
```

### Frontend

```bash
cd frontend
npm install
cp .env.example .env.local
```

### Backend

```bash
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

У Windows для активації середовища використовується команда:

```powershell
.venv\Scripts\Activate.ps1
```

## Змінні середовища

### Backend

| Змінна | Опис | Приклад |
|---|---|---|
| DATABASE_URL | рядок підключення до бази даних | sqlite:///./opero.db |
| SECRET_KEY | секрет для підпису JWT | change-me-to-a-long-random-secret |
| ACCESS_TOKEN_EXPIRE_MINUTES | строк дії access token у хвилинах | 60 |
| FRONTEND_ORIGIN | адреса frontend-застосунку | http://localhost:3000 |

Для Neon використовується рядок підключення PostgreSQL, отриманий у консолі Neon.

### Frontend

| Змінна | Опис | Приклад |
|---|---|---|
| NEXT_PUBLIC_API_URL | базова адреса FastAPI | http://localhost:8000/api/v1 |

## Налаштування бази даних

Локальна розробка використовує SQLite:

```text
DATABASE_URL=sqlite:///./opero.db
```

Після налаштування змінних середовища застосуйте міграції:

```bash
cd backend
alembic upgrade head
```

Команда створює таблиці користувачів, складів, товарів, залишків, рухів товарів, заявок, позицій заявок, задач і журналу дій.

## Запуск застосунку

Запустіть FastAPI:

```bash
cd backend
uvicorn app.main:app --reload --port 8000
```

Запустіть Next.js у другому терміналі:

```bash
cd frontend
npm run dev
```

- Інтерфейс: http://localhost:3000
- Swagger UI: http://localhost:8000/docs

## Опис API

| Група | Базовий шлях | Призначення |
|---|---|---|
| Auth | /api/v1/auth | вхід і дані поточного користувача |
| Users | /api/v1/users | керування користувачами |
| Warehouses | /api/v1/warehouses | склади та залишки |
| Products | /api/v1/products | товари та матеріали |
| Stock | /api/v1/stock-movements | надходження та історія рухів |
| Requests | /api/v1/requests | заявки, погодження, відхилення, видача |
| Tasks | /api/v1/tasks | задачі та зміна статусів |
| Dashboard | /api/v1/dashboard | показники системи |
| Audit | /api/v1/audit-log | журнал дій |

Повний контракт API доступний у Swagger UI після запуску backend.

## Типовий сценарій використання

1. Адміністратор створює склад, товари та облікові записи працівників.
2. Комірник реєструє надходження товару на склад.
3. Працівник створює заявку на видачу матеріалів.
4. Менеджер погоджує заявку.
5. Комірник видає погоджені позиції.
6. Система оновлює залишки, статус заявки та журнал дій.
7. Менеджер створює задачу для виконавця та контролює дедлайн на дашборді.

## Розгортання

Frontend і backend розгортаються на Vercel з одного репозиторію. SQLite призначена лише для локальної розробки та тестування. У preview і production-середовищах використовується Neon PostgreSQL через `DATABASE_URL`.

Перед використанням нової схеми бази даних необхідно застосувати міграції Alembic до Neon.
